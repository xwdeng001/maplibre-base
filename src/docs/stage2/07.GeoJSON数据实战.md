# 07. GeoJSON 数据实战

## 概述

GeoJSON 是 Web 地图中最常用的数据格式，本节深入学习 GeoJSON 规范和在 MapLibre 中的实战应用：

- GeoJSON 规范（RFC 7946）
- 七种几何类型
- Feature 与 FeatureCollection
- 动态加载与更新 GeoJSON
- 坐标系与投影

---

## GeoJSON 规范

GeoJSON 是一种基于 JSON 的地理数据编码格式，遵循 [RFC 7946](https://datatracker.ietf.org/doc/html/rfc7946) 规范。

### 结构层次

```
GeoJSON
├── Geometry          — 几何图形（7种类型）
├── Feature           — 要素 = 几何 + 属性
└── FeatureCollection — 要素集合
```

---

## 七种几何类型

### 1. Point — 点

```json
{
  "type": "Point",
  "coordinates": [116.39, 39.91]
}
```

### 2. MultiPoint — 多点

```json
{
  "type": "MultiPoint",
  "coordinates": [
    [116.39, 39.91],
    [121.47, 31.23]
  ]
}
```

### 3. LineString — 线

```json
{
  "type": "LineString",
  "coordinates": [
    [116.39, 39.91],
    [121.47, 31.23],
    [113.26, 23.13]
  ]
}
```

### 4. MultiLineString — 多线

```json
{
  "type": "MultiLineString",
  "coordinates": [
    [[116.39, 39.91], [121.47, 31.23]],
    [[113.26, 23.13], [104.07, 30.67]]
  ]
}
```

### 5. Polygon — 多边形

```json
{
  "type": "Polygon",
  "coordinates": [
    [
      [116.33, 39.95], [116.45, 39.95],
      [116.45, 39.87], [116.33, 39.87],
      [116.33, 39.95]
    ]
  ]
}
```

> ⚠️ 多边形的第一个和最后一个坐标必须相同（闭合环）。

### 6. MultiPolygon — 多面

```json
{
  "type": "MultiPolygon",
  "coordinates": [
    [[[116.33, 39.95], [116.45, 39.95], [116.45, 39.87], [116.33, 39.87], [116.33, 39.95]]],
    [[[121.40, 31.30], [121.55, 31.30], [121.55, 31.15], [121.40, 31.15], [121.40, 31.30]]]
  ]
}
```

### 7. GeometryCollection — 几何集合

```json
{
  "type": "GeometryCollection",
  "geometries": [
    { "type": "Point", "coordinates": [116.39, 39.91] },
    { "type": "LineString", "coordinates": [[116.39, 39.91], [121.47, 31.23]] }
  ]
}
```

---

## Feature — 要素

Feature 将 Geometry 与属性（properties）绑定：

```json
{
  "type": "Feature",
  "id": "bj001",
  "geometry": {
    "type": "Point",
    "coordinates": [116.39, 39.91]
  },
  "properties": {
    "name": "北京",
    "population": 21540000,
    "level": "直辖市"
  }
}
```

- `id`：可选，要素唯一标识
- `properties`：自定义属性对象，用于样式表达式和弹窗展示

---

## FeatureCollection — 要素集合

```json
{
  "type": "FeatureCollection",
  "features": [
    { "type": "Feature", "geometry": { ... }, "properties": { ... } },
    { "type": "Feature", "geometry": { ... }, "properties": { ... } }
  ]
}
```

**FeatureCollection 是 MapLibre GeoJSON 数据源最常用的格式。**

## 在 MapLibre 中使用 GeoJSON

### 添加 GeoJSON 数据源和图层

```ts
// 添加数据源
map.addSource('cities', {
  type: 'geojson',
  data: {
    type: 'FeatureCollection',
    features: [
      {
        type: 'Feature',
        geometry: { type: 'Point', coordinates: [116.39, 39.91] },
        properties: { name: '北京', pop: 2154 }
      }
    ]
  }
})

// 添加圆点图层
map.addLayer({
  id: 'cities-circle',
  type: 'circle',
  source: 'cities',
  paint: {
    'circle-radius': ['interpolate', ['linear'], ['get', 'pop'], 500, 5, 2000, 15],
    'circle-color': '#1890ff'
  }
})
```

### 动态更新数据

```ts
// 获取数据源并更新
const source = map.getSource('cities') as maplibregl.GeoJSONSource
source.setData(newFeatureCollection)
```

### 从远程 URL 加载

```ts
map.addSource('remote', {
  type: 'geojson',
  data: 'https://example.com/cities.geojson'
})
```

### 使用 fetch 加载后设置

```ts
const response = await fetch('/data/cities.geojson')
const geojson = await response.json()

const source = map.getSource('cities') as maplibregl.GeoJSONSource
source.setData(geojson)
```

## 坐标系与投影

### GeoJSON 坐标系

GeoJSON 使用 **WGS 84 (EPSG:4326)** 坐标系：
- 经度范围：-180 ~ 180
- 纬度范围：-90 ~ 90
- 坐标顺序：`[经度lng, 纬度lat]`（注意：不是 `[纬度, 经度]`）

### MapLibre 投影

MapLibre 内部使用 **Web Mercator (EPSG:3857)** 投影渲染，但数据输入仍使用 WGS 84。

> 💡 坐标顺序容易混淆：GeoJSON 是 `[lng, lat]`，与百度地图等 `[lat, lng]` 不同。

### 公司项目使用天地图时，要不要做坐标转换？

分两层看：**底图瓦片** 和 **业务 GeoJSON / 点位**。

| 场景 | 是否需要转换 | 说明 |
|------|----------------|------|
| MapLibre 加载天地图 **栅格/矢量瓦片** 作底图 | 一般 **不需要** | 天地图在线瓦片与 MapLibre 一样走 **Web Mercator** 切片；在样式里配好 `raster` / `vector` 的 `tiles` URL（含 key、`tileSize: 256` 等，见 [06. 数据源 Sources](./06.数据源Sources.md)）即可 |
| GeoJSON 来自 GPS、国际标准、公开 WGS 84 / **CGCS2000** 经纬度 | 一般 **不需要** | MapLibre 的 `geojson` 源按 **WGS 84 经纬度** 解释；国内政务与天地图常用 **CGCS2000**，与 WGS 84 在 Web 地图尺度下通常 **可直接叠加**，偏差远小于火星坐标 |
| GeoJSON 来自 **高德 / 腾讯** 等 | **需要** | 多为 **GCJ-02（火星坐标）**，直接写入 MapLibre 会与天地图底图 **偏移约百米级** |
| GeoJSON 来自 **百度** | **需要** | **BD-09**，需先转到 WGS 84 / CGCS2000 再 `setData` |
| 与天地图 JS API 混用同一批点位 | 先统一来源 | 天地图 API 点位多为经纬度（CGCS2000）；若业务里还有高德拾点，必须先统一到同一坐标系再进 MapLibre |

**实践建议：**

1. **只换底图为天地图、业务数据不变**：确认业务数据不是 GCJ-02 / BD-09；若是，在入库或 `setData` 前做转换。
2. **GeoJSON 写法不变**：转换后仍是 `FeatureCollection`，坐标顺序仍是 `[经度, 纬度]`，只是数值变成与底图一致的经纬度。
3. **如何转换**：可在服务端或前端用 `gcoord`、`coordtransform` 等库，例如 GCJ-02 → WGS 84；勿把「纬度、经度顺序」和「坐标系加密」两件事搞混。
4. **仍对不齐时**：查数据是否混用了多套坐标系、是否把 `[lat, lng]` 当成了 GeoJSON 的 `[lng, lat]`，以及瓦片 `bounds` / 范围是否写反。

```ts
// 示例：高德拾点（GCJ-02）要在 MapLibre + 天地图底图上显示时，先转 WGS 84 再写入 GeoJSON
// import gcoord from 'gcoord'
// const [lng, lat] = gcoord.transform([gcjLng, gcjLat], gcoord.GCJ02, gcoord.WGS84)

map.addSource('points', {
  type: 'geojson',
  data: {
    type: 'FeatureCollection',
    features: [{
      type: 'Feature',
      geometry: { type: 'Point', coordinates: [lng, lat] }, // 已是 WGS 84 / 与底图一致的经纬度
      properties: { name: '示例' }
    }]
  }
})
```

> �� > 💡 **小结**：天地图底图本身不要求你对瓦片做坐标转换；**要不要转，取决于业务 GeoJSON 是不是火星/百度坐标**。与天地图配套的自研数据、GPS、CGCS2000 导出，多数情况直接 `[lng, lat]` 即可。

## TypeScript 类型支持

安装 GeoJSON 类型定义：

```bash
pnpm add -D @types/geojson
```

使用类型：

```ts
import type { FeatureCollection, Feature, Point } from 'geojson'

const data: FeatureCollection = {
  type: 'FeatureCollection',
  features: []
}

const point: Feature<Point> = {
  type: 'Feature',
  geometry: { type: 'Point', coordinates: [116.39, 39.91] },
  properties: { name: '北京' }
}
```

---

## 本课小结

- GeoJSON 有 7 种几何类型：Point/MultiPoint/LineString/MultiLineString/Polygon/MultiPolygon/GeometryCollection
- Feature = 几何 + 属性，FeatureCollection 是要素集合
- MapLibre 通过 GeoJSON 数据源 + 图层来渲染 GeoJSON 数据
- `setData()` 可动态更新 GeoJSON 数据
- 坐标顺序为 `[经度, 纬度]`，使用 WGS 84 坐标系
- 天地图作底图时瓦片一般无需转换；业务数据若为 GCJ-02 / BD-09 需先转换再写入 GeoJSON
